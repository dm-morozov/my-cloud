# My Cloud — Облачное файловое хранилище

Персональное файловое хранилище на Django и React. Учебные материалы сохранены в `docs/netology/`.

Актуальный запуск: [Docker backend и GitHub Pages frontend](docs/deployment/docker-pages.md).
Репозиторий: [dm-morozov/my-cloud](https://github.com/dm-morozov/my-cloud).

Работающее приложение: [mycloud.mu56.ru](https://mycloud.mu56.ru/).
API: [cloud.mu56.ru](https://cloud.mu56.ru/api/users/csrf/).

`My Cloud` — персональное файловое хранилище: REST API на Django REST Framework и PostgreSQL, клиент на React и TypeScript. Можно загружать, искать, переименовывать и скачивать файлы, добавлять комментарии и создавать публичные ссылки.

Backend работает в Docker на Ubuntu VDS с Gunicorn, Nginx и HTTPS. Frontend размещён на GitHub Pages и публикуется через GitHub Actions. В демо установлены ограничения: до 20 МиБ на файл и 100 МиБ на пользователя.

Автор: **Дмитрий Морозов** · [Telegram](https://t.me/dem2014) · [GitHub](https://github.com/dm-morozov) · [Резюме](https://github.com/dm-morozov/resume-fullstack-py-js).

## ⚡ Основные возможности проекта

### 🧑‍💻 Для авторизованных пользователей
* **Регистрация и авторизация**: безопасная сессионная аутентификация с проверкой пароля и CSRF-защитой.
* **Интерактивное хранилище (Файловый менеджер)**:
  * Загрузка файлов любого типа с помощью интуитивного интерфейса **Drag-and-Drop** или стандартного проводника.
  * Возможность добавлять необязательные текстовые комментарии к загружаемым файлам.
  * Скачивание файлов с автоматической фиксацией даты последнего обращения.
  * Inline-редактирование (переименование файлов и изменение комментариев) без перезагрузки страниц.
  * Удаление файлов из базы данных и с диска.
* **Публичный доступ (Шеринг)**:
  * Генерация уникальной публичной ссылки с токеном доступа для файла.
  * Автоматическое копирование ссылки в буфер обмена.
  * Специальный публичный роут для скачивания файлов гостями системы (без необходимости авторизации).

### 👑 Для администраторов (Admin-панель)
* **Статистика пользователей**: вывод списка всех зарегистрированных пользователей системы с указанием ID, имени, email, роли, общего количества загруженных файлов и суммарного занимаемого места на диске (с автоматическим форматированием размера в B/KB/MB/GB).
* **Управление ролями**: переключение прав администратора (`is_staff`) по клику на бейдж пользователя с защитой от лишения прав самого себя.
* **Удаление учетных записей**: полное удаление пользователей и всех связанных с ними файлов с физического диска сервера (с защитой от удаления самого себя).
* **Просмотр чужих хранилищ**: возможность открыть список файлов любого пользователя и управлять ими (скачивать или удалять от лица администратора) с пересчетом общего объема занятого места в реальном времени.

## 🛠️ Стек технологий

### 🛡️ Backend
* **Python 3.12+**
* **Django 6** — веб-фреймворк.
* **Django REST Framework (DRF)** — построение RESTful API.
* **PostgreSQL** — основная реляционная база данных для хранения метаданных и связей.
* **python-decouple** — безопасная конфигурация через переменные окружения (`.env`).
* **Django Test Framework** — юнит- и интеграционное тестирование API.

### 🎨 Frontend
* **React 19**
* **TypeScript 6** — строгая типизация интерфейса.
* **Vite 8** — быстрый инструмент сборки и среда разработки.
* **Redux Toolkit** — централизованное управление состоянием приложения (`authSlice`, `filesSlice`, `adminSlice`).
* **React Router 7** — организация роутинга и защищенных маршрутов (Protected Routes).
* **CSS Modules (Vanilla CSS)** — изолированные стили компонентов, общие цветовые переменные и адаптивная вёрстка. Принципы интерфейса описаны в [frontend-design.md](docs/architecture/frontend-design.md).

## 🚀 Инструкция по локальному запуску

### 1. Клонирование репозитория
```bash
git clone https://github.com/dm-morozov/my-cloud.git
cd my-cloud
```

### 2. Настройка и запуск Backend

1. **Перейдите в директорию backend**:
   ```bash
   cd backend
   ```
2. **Создайте виртуальное окружение**:
   * *Windows*:
     ```bash
     python -m venv .venv
     .venv\Scripts\Activate.ps1
     ```
   * *Linux / macOS*:
     ```bash
     python3 -m venv .venv
     source .venv/bin/activate
     ```
3. **Установите зависимости**:
   ```bash
   pip install -r requirements.txt
   ```
4. **Создайте файл конфигурации `.env`**:
   Скопируйте пример окружения и заполните его своими доступами:
   * *Windows*:
     ```bash
     copy .env.example .env
     ```
   * *Linux / macOS*:
     ```bash
     cp .env.example .env
     ```
   Пример конфигурации:
   ```env
   SECRET_KEY=django-insecure-key
   DEBUG=True
   ALLOWED_HOSTS=127.0.0.1,localhost
   DB_NAME=cloud_storage
   DB_USER=postgres
   DB_PASSWORD=your_password
   DB_HOST=127.0.0.1
   DB_PORT=5432
   ```
5. **Создайте базу данных в PostgreSQL** (например, с именем `cloud_storage`), запустите СУБД и проверьте подключение.
6. **Примените миграции**:
   ```bash
   python manage.py migrate
   ```
7. **Создайте учетную запись Администратора**:
   ```bash
   python manage.py createsuperuser
   ```
8. **Запустите сервер разработки Django**:
   ```bash
   python manage.py runserver
   ```
   Сервер бэкенда будет доступен по адресу `http://127.0.0.1:8000/`.

---

### 3. Настройка и запуск Frontend

1. **Перейдите в директорию frontend**:
   Откройте новую вкладку терминала и выполните:
   ```bash
   cd frontend
   ```
2. **Установите зависимости Node.js** (рекомендуется использовать `npm` или `yarn`):
   ```bash
   npm install
   # или с помощью yarn
   yarn install
   ```
3. **Запустите сервер разработки Vite**:
   ```bash
   npm run dev
   # или с помощью yarn
   yarn dev
   ```
   Приложение будет доступно по адресу `http://localhost:5173/` (или по порту, который выведет Vite в консоль).

## 📡 Основные API-эндпоинты бэкенда

### Авторизация и пользователи (`/api/users/`)
* `POST /api/users/register/` — регистрация нового аккаунта.
* `POST /api/users/login/` — авторизация пользователя (устанавливает сессионную куку).
* `POST /api/users/logout/` — выход из системы с инвалидацией сессии.
* `GET /api/users/me/` — получение данных текущего авторизованного пользователя.
* `GET /api/users/` — получение списка всех пользователей со статистикой *(доступно только Администратору)*.
* `PATCH /api/users/<user_id>/` — изменение статуса прав администратора `is_staff` *(доступно только Администратору)*.
* `DELETE /api/users/<user_id>/` — полное удаление пользователя и всех его файлов *(доступно только Администратору)*.

### Управление файлами (`/api/files/`)
* `GET /api/files/` — получить список файлов. Обычный пользователь видит только свои файлы. Администратор может передать параметр `?owner_id=<user_id>` для просмотра файлов любого конкретного пользователя.
* `POST /api/files/` — загрузка нового файла на сервер с опциональным комментарием (передается в формате `multipart/form-data`).
* `GET /api/files/<file_id>/` — детальная информация о файле.
* `PATCH /api/files/<file_id>/` — переименование файла или обновление его комментария.
* `DELETE /api/files/<file_id>/` — удаление файла из БД и физического хранилища.
* `GET /api/files/<file_id>/download/` — скачивание файла пользователем/администратором (записывает время скачивания).
* `POST /api/files/<file_id>/public-link/` — генерация или получение существующего публичного токена доступа к файлу.

### Публичный доступ (`/api/public/`)
* `GET /api/public/files/<token>/` — скачивание файла сторонним пользователем по сгенерированному публичному токену (не требует авторизации в системе).

## 🔒 Безопасность и архитектурные особенности

* **Изоляция медиафайлов при тестах**: тесты модуля `files` используют временные переопределяемые директории для хранения тестовых файлов, что гарантирует чистоту основного `MEDIA_ROOT`.
* **Валидация на фронтенде и бэкенде**: формы регистрации, авторизации и переименования проходят многоуровневую проверку (на длину полей, формат почты, пароль, наличие спецсимволов).
* **Разделение ответственности на frontend**: API-клиент находится в `services/`, состояние — в Redux-срезах, интерфейс собирается из страниц и переиспользуемых компонентов. Формы имеют видимые подписи, модальное окно поддерживает клавиатуру и восстановление фокуса.

## 🌐 Деплой на продакшн-сервере (VPS)

Приложение успешно развернуто и доступно в продакшене по постоянному адресу:
* **Публичная ссылка на проект**: [http://80.78.254.193/](http://80.78.254.193/)
* Старое развёртывание ниже приведено для истории. Не применять его конфигурацию к новому серверу.

### Схема развертывания

- **Frontend**: GitHub Pages, собственный домен `mycloud.mu56.ru`, сборка и публикация через GitHub Actions.
- **Backend**: Ubuntu 24.04 LTS на Selectel VDS, отдельный Compose-проект в `/srv/projects/mycloud` с сервисами Django/Gunicorn, PostgreSQL и Nginx gateway.
- **HTTPS**: серверный Nginx принимает запросы к `cloud.mu56.ru` и передаёт их на loopback-порт gateway. База данных не публикуется наружу.
- **Данные**: PostgreSQL и загруженные файлы хранятся в постоянных Docker volumes.

Команды запуска, переменные окружения и настройки доменов: [руководство по развёртыванию](docs/deployment/docker-pages.md).
